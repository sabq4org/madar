# ما بعد المرحلة الأولى

## المرحلة الثانية: إثبات جودة الجمع

ابدأ بخمسة مصادر متفق عليها، وثلاث قنوات على الأكثر. سجل طريقة الوصول والحقوق والسرعة المتوقعة لكل مصدر. اجمع عينات حقيقية مع محرر، وقس اكتمال المواد، التأخير من وقت النشر، المواد المكررة، أخطاء الاستخراج، وتغير الروابط. لا تستخدم زمن الرصد بدل زمن النشر في تقييم السرعة.

أضف لوحة إدارة المصادر، تغيير عنوان التغذية مع تحقق جديد، سجل تدقيق للمشغلين، تنبيه تعطل المصدر، ومحدودية خروج شبكية على البنية. أضف موصل API لناشر متعاون قبل بناء زاحف عام.

## المرحلة الثالثة: جوهر مدار التحريري

اربط المواد بالأحداث، واستخرج الادعاءات إلى مقاطع مصدرية. احتفظ بتعارض المعلومات ومصدر كل معلومة. طوّر «ما تغيّر منذ آخر قراءة» بوصفه فروق حقائق تدعمها أدلة؛ تغير العنوان وحده لا يولّد تنبيهًا. ابدأ بمراجعة تحريرية ومجموعة تقييم عربية قبل النشر الآلي.

تُختبر الحالات: عشرة ناشرين ينقلون وكالة واحدة؛ تحديث الرقم؛ نفي الخبر؛ تعديل بلا معلومة؛ قصة قديمة يعاد تداولها؛ اختلاف أسماء الأشخاص. الاتفاق بين ناشرين لا يكفي لإثبات الاستقلال أو الصحة.

## المرحلة الرابعة: متابعة شخصية

حدد الهوية وسياسة بيانات المستخدم، ثم الحسابات وقواعد المتابعة وحالة آخر قراءة. تبدأ القواعد من حقائق قابلة للاختبار: «فتح التسجيل»، «بدء التنفيذ»، «تغيير الموعد». يجب أن تملك الإشعارات سجل تسليم ومنع تكرار وإيقافًا وتصحيحًا، وأن تخضع لإذن المستخدم وحدود واضحة.

## ما لا يُستعجل

الزحف الشامل، موصل X غير المرخص، نسخ النصوص والصور كاملة، إنشاء أخبار بالذكاء الاصطناعي دون إسناد، وتطبيقات iOS/Android قبل ثبات القيمة. يمكن مشاركة API لاحقًا مع التطبيقات. نقطة التفوق المستهدفة هي جودة متابعة تطور القصة، وليس عدد المصادر وحده.
