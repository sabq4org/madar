# تشغيل مدار على Railway

هذا الدليل يوثق إصلاح الخدمات التي أنشأها المستخدم على Railway في 2026-11-17، بعد تسليم الأساس المحلي. لا يفعّل مصادر أو ينشئ موارد مدفوعة تلقائيًا.

## الإعداد الفعلي

الخدمات الثلاث مرتبطة بالمستودع نفسه، مع جذر المستودع الكامل. رغم ظهور `RAILPACK` في إعداد builder، تؤكد سجلات البناء استخدام `Dockerfile` الموجود في الجذر وتنفيذ `pnpm build`. قاعدة PostgreSQL الخارجية يحددها المستخدم، ويجب أن تكون مخصصة لمدار. لا تنسخ اتصال القاعدة المحلية أو مفاتيح التطوير إلى الإنتاج.

| الإعداد                     | API                                        | Worker                              | Web                                                 |
| -------------------------- | ------------------------------------------ | ----------------------------------- | --------------------------------------------------- |
| Start command              | `pnpm --filter @madar/api start`           | `pnpm --filter @madar/worker start` | `node apps/web/.next/standalone/apps/web/server.js` |
| `DATABASE_URL`             | اتصال PostgreSQL السري                     | الاتصال نفسه                         | غير مطلوب                                           |
| `ADMIN_API_KEY`            | سر عشوائي مستقل، 32 محرفًا على الأقل         | غير مطلوب                           | غير مطلوب                                           |
| `NODE_ENV`                 | `production` صريح                          | `production` صريح                   | `production` صريح                                   |
| `HOST`                     | `::` لاستقبال الاتصال الداخلي عبر IPv4 وIPv6 | غير مطلوب                           | غير مستخدم بهذا الاسم                                |
| `HOSTNAME`                 | غير مستخدم                                 | غير مستخدم                          | `::` لاستقبال اتصال فحص الجاهزية                     |
| `API_PORT` / `PORT`        | `4100` لكليهما                             | غير مطلوب                           | `PORT=3100`                                         |
| `API_INTERNAL_URL`         | غير مطلوب                                  | غير مطلوب                           | `http://madarapi.railway.internal:4100`             |
| `ENABLE_NETWORK_INGESTION` | `false` صريح                               | `false` صريح                        | غير مطلوب                                           |
| Pre-deploy                 | `pnpm db:migrate`                          | لا يوجد                              | لا يوجد                                              |
| Healthcheck                | `/health/ready`، مهلة 120 ثانية            | لا يقدّم HTTP                         | `/`، مهلة 120 ثانية                                 |

عنوان API الداخلي أعلاه هو الاسم الحالي الذي أعادته Railway لهذا المشروع. في مشروع آخر استخدم قيمة `RAILWAY_PRIVATE_DOMAIN` لخدمة API. الربط خاص داخل البيئة؛ لا يحتاج نشر API على نطاق عام. يتوافق الإعداد مع [توثيق الشبكة الخاصة](https://docs.railway.com/networking/private-networking) و[إعداد المكتبات](https://docs.railway.com/networking/private-networking/library-configuration).

## الترحيلات والجاهزية

- `pnpm db:migrate` ينفذ الترحيلات الموجودة فقط، بقفل PostgreSQL وتحقق checksum؛ لا يعيد ضبط القاعدة ولا يزرع بيانات تجريبية.
- يُنفَّذ الأمر من جذر المستودع. يحتاج `tsx` وملفات `scripts` و`packages/db/migrations` داخل صورة التشغيل؛ نجح بالفعل مع صورة Docker المستخدمة بتاريخ التحقق.
- ضع الترحيلات في [Pre-deploy](https://docs.railway.com/deployments/pre-deploy-command) لخدمة API، وليس في build الذي قد لا يصل إلى شبكة التشغيل.
- نجاح `/health/ready` يثبت اتصال القاعدة ووجود الترحيلات الثلاثة المطلوبة. نجاح `/` وحده لا يثبت سلامة API؛ راجع أيضًا استجابات `/v1/articles` و`/v1/sources` التي تطلبها صفحة الويب.
- تشغيل Web يستخدم standalone، مع الملفات الثابتة والخطوط التي ينسخها `scripts/prepare-web.mjs` أثناء `pnpm build`؛ لا تستخدم `next start` مع إعداد `output: 'standalone'` الحالي.
- لا تشغّل اختبارات التكامل أو `db:seed` على قاعدة الإنتاج. اختبارات التكامل تستخدم قاعدة محلية مؤقتة مستقلة.

## تفسير الأعطال المرصودة

| السجل أو العَرَض                                     | السبب والإجراء                                                                                                             |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `Invalid environment fields: DATABASE_URL`         | قيمة الاتصال غائبة أو لا تجتاز التحقق؛ أضف رابط PostgreSQL الكامل إلى API وWorker.                                          |
| `ADMIN_API_KEY is required for the production API` | مفتاح الإدارة غائب؛ أدخله في API فقط، ولا تعطل شرط المصادقة.                                                                |
| `Server listening at http://127.0.0.1:4100`        | الخدمة تستقبل داخل الحاوية فقط؛ اضبط `HOST=::`.                                                                           |
| `SCHEDULER_FAILED` مع عدم وجود جداول التطبيق       | اتصال القاعدة يعمل لكن الترحيلات لم تنفذ؛ تحقق من مخطط القاعدة ثم شغّل الترحيلات. لا تفترض أن كل خطأ بهذا الرمز سببه الجداول. |
| الواجهة تعمل لكن تعرض خطأ الخدمة                   | تحقق من `API_INTERNAL_URL` ومن منفذ واستماع API واستجابة مسارات القراءة.                                                  |

تحديث المتغيرات يعيد نشر الخدمة. احتفظ بالأسرار في Railway، ولا تضعها في المستودع أو السجلات. ظهر نطاق Web العام أثناء المتابعة: [مدار](https://madarweb-production.up.railway.app)، بمنفذ هدف 3100؛ لم ينشئه المساعد. نجح فحص HTTPS لصفحتي الرئيسية والمصادر، وبقي API خاصًا دون نطاق عام. فحص النسخ الاحتياطي والاستعادة والحمل وتفعيل المصادر تظل متطلبات قبل الإطلاق الفعلي.
