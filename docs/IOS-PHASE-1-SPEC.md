# مدار على iOS — النسخة التفاعلية الأولى

## القرار والنطاق

طلب المستخدم في 17 نوفمبر 2026 بدء **تطبيق مدار الجديد** على iOS، وأرفق التصور الأزرق ذي الشاشات الثلاث. هذا امتداد مصرح لنطاق المرحلة الأولى، التي كانت تؤجل تطبيقات المتاجر؛ التنفيذ هنا تطبيق محلي للمحاكي، وليس إصدارًا للمتجر أو توصيلًا للأخبار الحية.

المرجع البصري هو `apps/web/public/prototype.html`: الخلفية البيضاء، كحلي `#172B46`، أزرق `#245BE8`، مساحات هادئة `#EDF3FF`، رمادي نصوص مرجعي `#687D9A` (دُكّن إلى `#566B87` في التطبيق لتحسين التباين) وفواصل `#DFE7F1`. الخط IBM Plex Sans Arabic محلي بترخيص OFL. الواجهة عربية RTL، والعناصر الأصلية لـiOS تتولى التنقل والتمرير والأحجام المتغيرة للنص. البطاقة الرئيسية تحمل خريطة خط نقل مرسومة داخل التطبيق؛ لا صور خارجية ولا شريط حالة مزيف.

## ما يستطيع المستخدم تجربته

- **اليوم:** قصتان افتراضيتان، الفرق منذ القراءة، وفتح ملف القصة.
- **داخل القصة:** ما تغير، تسلسل التطورات، المعروف وغير المعلن، والأدلة الافتراضية منفصلة في تبويبها.
- **المتابعة:** اختيار تطور محدد لكل قصة، حفظه أو تعديله أو إلغاؤه.
- **المحفوظات:** حفظ القصة والعودة إليها، مع حالات فراغ واضحة.
- **تجربة التحديثات:** سيناريوهات معدة مسبقًا، تنبيه داخل التطبيق عند مطابقة الاختيار، وإعادة نشر لا تضيف تنبيهًا أو نسخة أخرى.

تُحفظ المتابعة والمحفوظات والقراءة والتحديثات والتنبيهات داخل الجهاز، وتستمر بعد إغلاق التطبيق. إعادة ضبط التجربة إجراء صريح بتأكيد داخل الواجهة. التنبيهات في هذه النسخة عناصر داخل التطبيق فقط.

## البنية والعقود

- `apps/ios/Madar.xcodeproj`: مشروع Xcode مشترك بلا مولّد خارجي، الحد الأدنى iOS 17. يستخدم مجلدات متزامنة تدعمها Xcode 16 فأحدث.
- `apps/ios/Madar`: مدخل SwiftUI وواجهات وموارد محلية.
- `apps/ios/MadarCore`: حزمة Swift محلية بلا اعتماديات خارجية، تحتوي نماذج القصص وسيناريوهاتها ومتجر الحالة واختباراته.
- نموذج الحالة محفوظ في مفتاح واحد ذي إصدار في UserDefaults. معرفات السيناريوهات ثابتة، وإعادة تنفيذها بعد تشغيل التطبيق مجددًا لا تكرر الأثر.
- كل قصة ومصدر وتحديث يحمل بيانًا صريحًا بأنه افتراضي وسياسة حقوق. المصادر لا تُنسب إلى ناشرين حقيقيين ولا تفتح روابط مختلقة.
- معرف الحزمة المؤقت `org.madar.preview`؛ اختيار معرف التوزيع والتوقيع يتم عند تجهيز نسخة الجهاز أو المتجر.

لا توجد اتصالات شبكية أو صلاحيات إشعارات أو حسابات أو تحليلات استخدام. السيناريوهات تُحدَّد يدويًا؛ نجاحها لا يثبت وجود خوارزمية تميّز التطور الواقعي من إعادة الصياغة. لا تتغير قاعدة البيانات أو API أو خدمة الويب.

## معايير القبول

1. نجاح اختبارات الحزمة للمطابقة وعدم المطابقة، ومنع التكرار بعد إعادة التحميل، واستمرار الحفظ والقراءة، وحماية الحالة التالفة.
2. نجاح بناء التطبيق لمحاكي iPhone، ثم فتحه وفحص التفاعل بصريًا.
3. فحص الشاشات المرجعية الثلاث والحفظ والمتابعة والمصادر والمحاكاة، مع حالة فراغ ومراجعة نص مكبّر/شاشة صغيرة.
4. تسجيل الأدلة والحدود الفعلية في `docs/ACCEPTANCE.md`؛ بناء المحاكي لا يعني قبول App Store أو اختبار جهاز فعلي.

## لاحقًا

ربط القصص يتطلب عقد API خاصًا بالأحداث والتطورات ومراجعها؛ API المقالات الحالي ليس هذا العقد. قبل التنبيهات الحقيقية نحتاج هوية المستخدم، مزامنة التفضيلات، سياسة خصوصية وموافقات، وتقييم جودة التطورات. نشر TestFlight والتوقيع والإطلاق مراحل منفصلة.
