# قبول المرحلة الأولى

تاريخ التحقق المحلي: 2026-11-17. البيئة: macOS، Node 26.12.1، pnpm 11.25.0، PostgreSQL 17.10 في عنقود خاص بالمشروع. المرجع المستمر لفحوص كل commit هو [GitHub Actions](https://github.com/sabq4org/madar/actions/workflows/ci.yml).

## الأدلة المنفذة

| الاختبار                                | النتيجة                                                                                                               |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `pnpm install --frozen-lockfile`       | نجح، مع تصريح build scripts محدد في pnpm                                                                              |
| `pnpm lint`                            | نجح باستخدام إعداد Biome recommended                                                                                  |
| `pnpm typecheck`                       | نجح للحزم والتطبيقات والاختبارات والسكربتات                                                                            |
| `pnpm test`                            | 8 اختبارات وحدة نجحت؛ تشمل RSS/Atom/XML declaration والكيانات والروابط وDNS والمهل وحجم الرد والإلغاء و304 ومنع الشبكة |
| `pnpm test:integration`                | 11 اختبارًا نجحت على قاعدة PostgreSQL مؤقتة مستقلة وحُذفت بعد انتهاء الاختبار                                            |
| `pnpm build`                           | نجح بناء API والعامل وصفحات Next.js، وتجهيز standalone والملفات الثابتة                                               |
| `node scripts/smoke.mjs`               | نجح على الخدمات المبنية: الطابور ← قاعدة البيانات ← API ← صفحة الويب، مع نسخ المادة والخط والنموذج البصري             |
| `pnpm audit --prod --audit-level=high` | لم تُبلغ الأداة عن ثغرات معروفة وقت الفحص؛ لا يمثل ضمانًا بعد تحديث التبعيات                                              |
| فحص المتصفح                            | رُصدت المواد التجريبية وصفحة التفاصيل وسجل النسخ وصفحة المصادر؛ لم تظهر أخطاء JavaScript في السجل الذي فُحص             |

تغطي اختبارات التكامل إعادة الترحيلات، الجاهزية، منع التكرار بما فيه الجمع المتزامن، حفظ تغير A→B→A، المؤشر عند تساوي الأوقات، مصادقة الإدارة ومدخلاتها، حجب المصدر المسحوب، منع البيانات التجريبية في الإنتاج، تطبيق تغيير سياسة المقتطف أثناء الجلب، استهلاك الطابور، ونقل مهمة فاشلة إلى طابور الفشل.

## مراجعة مستقلة وإصلاحات

فُصل تنفيذ موصل الجمع والواجهة عن مراجعة المنسق، ونُفذت مراجعة مستقلة للخدمات. أُصلح فحص الجاهزية ليشمل جميع الترحيلات المطلوبة، وأعيد تطبيق سياسة المقتطف داخل معاملة الحفظ بعد قفل المصدر. أضيفت اختبارات تمنع رجوع العيبين. كما أُصلحت معالجة304 واختيار جذر XML وإلغاء الردود المرفوضة بدل استهلاكها بلا حدود.

## الحدود المعلنة

- لم يُشغّل Docker على الجهاز المحلي لأنه غير مثبت. مهمة CI مستقلة تبني الصورة وتشغّل Compose وتزرع المصدر التجريبي وتنفذ smoke؛ حالة تشغيلها الفعلية ظاهرة في رابط Actions، ولا تُستنتج من وجود الملف فقط.
- لم تُربط مصادر إخبارية حقيقية ولم يُجرَ زحف خارجي. الاختبارات الشبكية تستخدم نقلًا وDNS محاكيين؛ مسار الطابور والتخزين والعرض يعمل على بيانات تجريبية فعلية داخل القاعدة.
- لم تُنشأ موارد سحابية أو تُنشر خدمة عامة. لا مصادقة مستخدمين أو تنبيهات أو ذكاء اصطناعي أو تطبيق متجر.
- لم يُختبر استرجاع نسخة احتياطية أو تحمل حمل إنتاجي. خطة التشغيل توثق المتطلبات قبل الإطلاق.
- فحص العرض في المتصفح كان مكتبيًا. توجد قواعد CSS للجوال، لكن محاولة ضبط viewport بالأداة لم تغير أبعاده؛ لا ندعي اختبار جهاز جوال فعلي.

نتيجة المرحلة: أساس محلي قابل للتشغيل والاختبار والتطوير اللاحق، مع فصل واضح بين المنتج التجريبي وميزات مدار التحريرية المستهدفة.

## متابعة تشغيل Railway — 2026-11-17

هذه متابعة لاحقة للمرحلة المحلية: أنشأ المستخدم الخدمات الثلاث على Railway وربط قاعدة PostgreSQL خارجية وأدخل مفتاح الإدارة. توثيق الإعداد في [RAILWAY.md](RAILWAY.md). لم تنشئ هذه المعالجة قاعدة أو خطة مدفوعة جديدة.

الأسباب المثبتة بالسجلات والفحص: غياب `DATABASE_URL` أولًا، ثم غياب `ADMIN_API_KEY` في API؛ وبعد زوال الكراش بقي الاستماع على loopback فقط، ولم توجد جداول التطبيق، ولم يكن `API_INTERNAL_URL` مضبوطًا في Web. فشل المجدول هنا تزامن مع غياب الجداول؛ لا يُعمّم هذا التفسير على كل `SCHEDULER_FAILED`.

نُفذت إعدادات الاستماع الداخلي والمنافذ وبيئة production، وترحيلات API قبل النشر، وفحص `/health/ready`، وربط Web بالعنوان الداخلي لخدمة API. استُخدمت الترحيلات الثلاثة الموجودة دون تعديلها، وأُبقي الجمع الشبكي معطلًا صراحةً. بدأ Worker مجددًا دون أخطاء مجدول في السجلات التي فُحصت بعد الترحيل.

لم تُفعّل مصادر أخبار أو تُزرع بيانات fixtures في الإنتاج. لم ينشئ المساعد نطاقات عامة؛ ظهر نطاق Web العام أثناء المتابعة وفُحص عبر HTTPS كما سبق، وبقي API بلا نطاق عام. يظل تنبيه الفاتورة المتأخرة ظاهرًا في آخر معاينة لحساب Railway، ولم يُجرَ إجراء مالي. اختبارات الاستعادة والحمل وتفعيل المصادر والمراجعة البصرية العامة لا تزال خارج هذا التحقق.

## نموذج تصميم الويب — 2026-11-17

بطلب المستخدم تصميم الويب أولًا، أُضيف مسار محلي مستقل `/design` دون تعديل الصفحة الرئيسية أو عقود API أو قاعدة البيانات. يوثق [WEB-DESIGN.md](WEB-DESIGN.md) الاتجاه البصري وحدود النموذج. البيانات والمصادر افتراضية ومعلنة في الواجهة؛ الصور والخطوط محلية.

| الدليل                                          | النتيجة                                                                                                                                                         |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm exec biome check apps/web/src/app/design` | نجح دون أخطاء أو تحذيرات بعد التعديلات النهائية.                                                                                                                 |
| `pnpm --filter @madar/web build`                | نجح، بما فيه TypeScript؛ ظهر `/design` كصفحة ثابتة.                                                                                                             |
| `node scripts/prepare-web.mjs`                  | نجح تجهيز standalone مع مجلد الصور المحلي. شُغلت النسخة المبنية على المنفذ المحلي 3101 وفُحصت في المتصفح.                                                         |
| التفاعلات                                        | فُحص البحث والفلاتر وحالة عدم وجود نتائج والحفظ وقائمة المحفوظات والمتابعة وقائمتها؛ الملخص يفتح تفاصيل القصة، والمصادر والسياق يعرضان محتوى مختلفًا.              |
| لوحة المفاتيح                                   | فُحص إغلاق التفاصيل بـEscape واستعادة التركيز؛ فتح قصة من الملخص ثم إغلاقها يعود إلى الملخص، وإغلاقه يعيد التركيز إلى زر فتحه.                                      |
| تجاوب الواجهة                                   | فحص مكتبي ومحاكاة viewport عند 360 و390px؛ تساوى عرض الصفحة وعرض محتواها دون تمدد أفقي. القائمة وتفاصيل القصة قابلة للاستخدام، مع تمرير داخلي للحوار عند الحاجة. |
| مراجعة مستقلة                                   | عولج اختلاف حالة المتابعة بين الأزرار والفلاتر بتوحيدها حسب التصنيف، واستُبدلت دلالات tabs غير المكتملة بأزرار `aria-pressed` ضمن مجموعة معنونة.                      |
| أدلة بصرية                                      | حُفظت صور `desktop.jpg` و`mobile.jpg` و`story-detail.jpg` في مخرجات المحادثة `outputs/madar-web-design/`.                                                        |

هذه مراجعة نموذج محلي، وليست قبولًا لمنتج أخبار متصل. الحفظ والمتابعة مؤقتان في ذاكرة الصفحة. لم يُجرَ نشر للتصميم أو تفعيل مصادر أو تشغيل إشعارات. لا تتضمن هذه الإضافة تغيير backend أو schema، لذلك اقتصر تحققها على الواجهة والبناء؛ لم تُعد اختبارات قاعدة البيانات لهذه الإضافة. الاختبار المتجاوب محاكاة متصفح، وليس جهازًا فعليًا أو تدقيق إتاحة شاملًا.

### متابعة طلب الرفع والدمج

بعد المعاينة ونقل معرفة المشروع إلى Claude، طلب المستخدم رفع العمل ودمجه. يتضمن التغيير مسار `/design` في بناء الإنتاج؛ لذلك استُبدل وصف النموذج «محلي» بـ«تجريبي» في نص الواجهة وبيانات الصفحة، مع إبقاء تنبيه المحتوى الافتراضي و`noindex` وفصله عن واجهة الأخبار. عبارة عدم النشر أعلاه تصف وقت المعاينة الأولى. نجح `pnpm check` قبل الرفع، بما فيه فحص التنسيق والأنواع و8 اختبارات وحدة وبناء التطبيقات؛ نتائج CI والنشر اللاحقة تُراجع من سجل التشغيل الفعلي، ولا تُستنتج من نجاح الفحص المحلي.
